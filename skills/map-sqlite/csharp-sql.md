# The C# half, the T-SQL half, and the links between them

Everything in [SKILL.md](SKILL.md) holds; this is what `lang = 'csharp'` and `lang = 'sql'` add.

## C# (`files.lang = 'csharp'`)

Rows are SEMANTIC where a compilation could be built (`files.semantic = 1`): the half reads each project's
`.csproj`, its `project.assets.json` and the build's own record (`obj/**/structuregate.inputs.tsv` where
`StructureGate.targets` is imported) and binds with Roslyn, one compilation per project. No project, no
references → `files.semantic = 0` and every resolved column is `""`. **An empty resolved column is the
honest answer, never a guess** - and an unbound call (`symbol = ''`) is a MAYBE, not a "no caller": count it
before concluding a method is dead.

* **`calls.symbol`** is the method the call RUNS (`Namespace.Type.Method`), `callee` only what the code
  spells. "Who calls X" is `WHERE c.symbol = '...'`, never `callee LIKE`.
* **`arguments`**: `call` joins `calls.id` (or `object` joins `objects.id`), `name` is the parameter the
  argument reaches, `symbol` what the argument binds to, **`const` the value when the compiler or the
  folding pass knows it** - `const_kind` is `const` (the compiler), `folded` (an interpolation or
  concatenation followed operand by operand to its declarations), `enum` (`Demo.Region.US`; a cast naming
  no member reads `Demo.Region=6`). A local or field folds only where nothing writes it again, so the value is
  the one READ there. A piece that cannot be known folds to NOTHING: half a path looks like a path. A string that does not fold whole has
  `template` instead - JSON, each string it can be as literal text and `{"hole": "<C# source>"}` pieces.
* **`refs`**: one row per bound identifier that is not a call - `kind` (`field`, `property`, `namedtype`,
  `method` as a group or delegate), `name`, `symbol`. "Which code reads this property" is this table - writes
  (`x.P = ...`) and uses inside lambdas included. A member access the compiler could NOT bind (a lambda whose
  type it could not infer, a file with compile errors) is a row with `kind = 'unbound'` and `symbol = ''`: a
  MAYBE, found by name - `WHERE symbol = 'Ns.T.P' OR (kind = 'unbound' AND name LIKE '%.P')`. `diagnostics`
  says why it did not bind.
* **`objects`**: a construct - `kind` is `tuple`, `array`, `collection`, `initializer` - whose slots are
  `arguments` rows carrying an `object` id instead of a `call` id. `new Foo(x)` stays a CALL.
* `decorators` are the attributes (`DllImport`, `Fact`, ...); `exports` the public types (`kind` `class`,
  `record`, ...); `imports` the `using`s (`kind = 'using'`); `diagnostics` every compile error, and
  `files.errors` its count.
* `files`: `project`, `compiled` (0 for a `<Compile Remove>`), `generated` (listed, never walked:
  `<auto-generated>`, `.Designer.cs`, `.g.cs`), `excluded` (a `--map-exclude` glob matched - EF
  `Migrations/` on a large solution: compiled so the rest binds, no rows of its own), `razor` (`component`/`view` for a
  `.razor`/`.cshtml`, compiled as the C# the Razor compiler generates and walked as the MARKUP file at its
  own lines), `errors`, `semantic`.
* `razor_renders`: a component that renders another (`component` the full type name, `tag`, `attributes`).
* `handlers` adds `guard` (the `when` filter), `finally` and `symbol` (the bound exception type).
* **`enums` and `switch_cases` are SHARED with the TypeScript half**, in its shape, so one query reads both
  languages: tell them apart by `files.lang` through `file`/`owner_file` (a TypeScript row also carries `half`,
  a column that exists only once the TypeScript half has written). `enums`:
  `name`, `symbol`, `underlying`, and `members` - `[{name, value}]` with the NUMBER the compiler folded, or
  read off the source where C# defines it alone (a literal, the previous member + 1); `null` where it would
  need a lookup. Each member is still a `consts` row too (`cls` = the enum). `switch_cases`: one row per
  `case` section (`kind = 'case'`) and per switch-expression arm (`kind = 'arm'`, `result` = what it
  evaluates to); `branch` joins the switch's `branches` row (`kind = 'switch'`); `labels` as written,
  `label_symbols` what each binds to, `label_values` its constant (an enum member's number), `guard` the
  `when`, `is_default`. Every row INSIDE a section or an arm (a `returns`, a call, a literal, a nested switch's
  cases) carries `case` = that `switch_cases.id`, as a TypeScript row does: `return 1;` under `case Extra:` is
  what the method returns for Extra, not always.
* **`members`, `locals` and `comments` are shared too**, C# rows told apart by `files.lang`.
  - `members`: one row per property, field (each declarator), `const`, event and indexer, with `kind`, `symbol` (the name
    `refs.symbol` uses, so a use joins its declaration), `class_symbol`, `type` (resolved) and `type_text`,
    `static`, `readonly`, `visibility`, `accessors` (`["get", "private set"]`), `attributes`, `initializer` and `doc`.
    The containing type is `cls` and `class_symbol`, never the TypeScript half's `class` id.
  - `locals`: every variable a body declares. `declared` is one of `local`, `const`, `using`, `for`, `foreach`, `out`,
    `pattern` or `deconstruction`. Each row has `type` (resolved, so a `var` reads as its type), `type_text`, `source`
    (the initializer), `reads` and `calls`.
  - `comments`: `line`, `col`, `kind` (`line`, `block`, or `doc` for `///`), `context` (the declaration it sits in or
    documents, `Account.Reference`) and `text`. A `.razor`/`.cshtml` file has none.

A C# file is read again when it, its project file, its `project.assets.json` or the build's record moved;
a generated file is listed and never walked (nearly all of a real tree's rows were EF model snapshots).

## SQL (`files.lang = 'sql'`)

Every `.sql` under a `.sqlproj`, parsed with Microsoft's own T-SQL parser (ScriptDom):

| table | one row per |
|---|---|
| `sql_objects` | table, view, procedure, function, trigger, type, sequence, index - `database`, `schema`, `name`, `source` |
| `sql_columns` | column - `type`, `nullable`, `identity`, `key`, `default_expr`, `computed` |
| `sql_keys` | primary, unique, foreign (`ref_schema`, `ref_name`, `ref_columns`), check, default, index |
| `sql_refs` | what a statement touches - `action` (`select`, `insert`, `update`, `delete`, `merge`, `truncate`, `exec`, `include`), the column where it names one |
| `sql_steps` | what a script does, in order: `values`, `set`, `temp`, `drop`, `flow` - the input of `sql_seeds` |
| `sql_dynamic` | a `CREATE TRIGGER` inside a string - `name` (its literal prefix when `open` = 1: `'... T_' + @t`) |
| `files` | `database`, `project`, `kind`: `build`, `predeploy`, `postdeploy`, `script` |

SQLCMD is handled before parsing: `:r`/`:setvar` lines are blanked and `$(Var)` becomes an identifier of
the same length, so lines still point into the file; each `:r` becomes an `include` ref. `inserted`,
`deleted`, `#temp`, `@table` and CTE names are never touches.

Two tables are DERIVED after both halves and rewritten whole each run:

* **`sql_links`** joins C# to the database. `kind`: `ef_table` (a `ToTable(name, schema)` call → the table,
  `entity` the mapped class), `ef_column` (each column → the entity property of the same name, or
  `no property`), `ef_trigger` (`HasTrigger`), `sql_text` (a SQL string in C# - Dapper `SqlMapper.*`,
  `CommandDefinition`, EF `FromSqlRaw`/`ExecuteSqlRaw`/`SqlQueryRaw` → each object it touches), `sql_ref`
  (a view/proc/trigger/script statement → its object, in ITS OWN database), `sql_include` (`:r` → file).
  `status`: `bound`; `ambiguous` (several databases have it and no `default` decides - `database` is empty,
  `detail` lists them; where the config's `default` decides, the row is `bound` and `detail` reads
  `default of A, B`); `missing`; `system` (SQL Server's own catalog); `unknown` (SQL whose holes name what it
  touches); `partial` (the known tables of such SQL are bound beside it, and this row is the part built at
  run time - `dbo.{name}_Rows`); `dynamic` (a trigger a script builds by dynamic SQL, `detail`
  naming the script line and the VALUES row); `unparsed` (`detail` has the parser's error). A hole in a
  value position (`= {id}`, `IN ({ids})`, `TOP ({n})`) leaves the tables `bound`, `detail` naming the holes.
  An EF mapping applied to several contexts (`unattributedContexts`) has one `ef_table` row per database
  holding the table. `object` is the `sql_objects.id`, `column_id` the `sql_columns.id`. Which database a
  `DbContext` or a connection name reaches is the consumer's `structuregate.sql.json`, never guessed.
* **`sql_seeds`**: one row per VALUES tuple a deploy script writes and the table it lands in, the `:r`
  chain walked as SQLCMD runs it - `schema`/`name`/`object` the target, `via` the `#temp`/`@table` chain,
  `columns` + `row_values` (JSON, pairwise, as the table holds it after the deploy), `defaults` (columns
  the INSERT left out that a constant DEFAULT filled), `updates` (`file:line` of each later UPDATE),
  `condition` (`'$(Mode)' = 'A'`), `root`/`deployed`, `unbound` (values not known before run
  time), `status` `bound`/`partial`/`temp`.

* **`seed_<schema>_<table>`**: a typed VIEW per seeded table - one column per column any seed row sets, read
  by NAME whatever order the INSERT listed it, beside `id, file, line, database, condition, status` (a clash is
  `<table>_<column>`). `SELECT ItemID, Name, condition FROM seed_Demo_Items WHERE status = 'bound'`.
  A later UPDATE with a join or another WHERE, and any DELETE, is NOT applied: those rows still read as seeded.
  Compare a deployed database only with the rows whose `condition` its SQLCMD values allow.
* **`duplicate_types`**: a type name declared in more than one place (a symbol in a project - a `partial`
  class is one), with every place, and for an enum `members_differ` + `detail` naming each member set.

**`structuregate.sql.json`** (beside the exe, or `--sql-config <file>`; paths relative to it) says what code
cannot - which database a context or a connection reaches is decided at run time:

```json
{ "databases": [ { "name": "Main", "project": "../src/App.DB/App.DB.sqlproj",
                   "contexts": ["App.Data.MainContext"], "connections": ["db"] } ],
  "sqlText": ["Demo.Data.Sql.Run*"], "unattributedContexts": ["App.Data.MainContext"], "default": "Main" }
```

`contexts`: a mapping class with that context in `typeof(...)`, or an entity with a `DbSet` in it, resolves
there. `connections`: a method spelling that connection name runs its SQL there. `sqlText`: more methods whose
SQL argument is parsed (`*` the only wildcard). `unattributedContexts`: where a mapping class naming no context
is applied. Without the file a name links only where exactly one database has it - fewer links, none guessed.

## Worked queries

```sql
-- who calls a C# method, by what it BINDS to
SELECT f.path, c.line FROM calls c JOIN files f ON f.id = c.file
WHERE f.lang = 'csharp' AND c.symbol = 'Demo.Core.Services.OrderExporter.StatusOf';

-- how well C# is bound (a count to report)
SELECT count(*) calls, round(100.0 * sum(c.symbol <> '') / count(*), 2) bound
FROM calls c JOIN files f ON f.id = c.file WHERE f.lang = 'csharp';

-- every argument a method is ever given, with the values the compiler or the fold knows
SELECT a.name, a.const, a.const_kind, count(*) n FROM arguments a JOIN calls c ON c.id = a.call
WHERE c.symbol = 'Demo.Pricing.Discount' GROUP BY a.name, a.const ORDER BY a.name, n DESC;

-- where a member is declared, from any of its uses
SELECT DISTINCT f.path, m.line, m.kind, m.class_symbol FROM refs r JOIN members m ON m.symbol = r.symbol
JOIN files f ON f.id = m.file WHERE r.symbol LIKE '%.Reference';

-- a backend enum member and every C# switch that handles it, by the member's NUMBER
SELECT json_extract(m.value, '$.name') member, f.path, s.line, s.guard
FROM enums e JOIN files ef ON ef.id = e.file, json_each(e.members) m,
     switch_cases s JOIN files f ON f.id = s.file, json_each(s.label_values) v
WHERE ef.lang = 'csharp' AND e.name = 'Kinds' AND s.discriminant_type = e.symbol
  AND v.value = CAST(json_extract(m.value, '$.value') AS TEXT);

-- which components render a component, and where
SELECT f.path, r.line, r.attributes FROM razor_renders r JOIN files f ON f.id = r.file
WHERE r.component GLOB '*.Badge';

-- which entity and mapping maps a table, and in which database
SELECT l.entity, l.database, f.path, l.line FROM sql_links l JOIN files f ON f.id = l.file
WHERE l.kind = 'ef_table' AND l.name = 'Items';

-- every C# method whose SQL touches a table, and how
SELECT f.path, l.func, l.action FROM sql_links l JOIN files f ON f.id = l.file
JOIN sql_objects o ON o.id = l.object WHERE o.schema = 'Sales' AND o.name = 'OrderLines';

-- which seed scripts write a table
SELECT DISTINCT f.path FROM sql_links l JOIN files f ON f.id = l.file
JOIN sql_objects o ON o.id = l.object WHERE l.kind = 'sql_ref' AND l.action = 'insert' AND o.name = 'Categories';
```
