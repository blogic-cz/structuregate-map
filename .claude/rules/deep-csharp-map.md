# The deep C# map (`--map-sqlite`)

Moved out of CLAUDE.md so it loads only when this code is touched. Every paragraph is a scar: each rule
exists because breaking it once produced output that looked right. What a consumer queries is
`skills/map-sqlite/csharp-sql.md`; keep it in step.

C# IS A CONVERSATION WITH THE STORE, NOT A LAUNCH (`rust/fbtcore/src/mapper/deep/driven.rs`): rust asks the store
what it holds (files, shas, spent ids), asks C# only what .NET alone can answer (a file's project, the send order,
a batch's rows), stores each batch, drops the files that left, and the DONE count is read BACK out of the database,
never counted off what was sent. C# never opens SQLite. Batches are bounded by ROWS, not files - building every
row before sending any answered `Out of memory`.

THE STORE IS A CACHE, NEVER A SOURCE (`rust/fbtcore/src/rows/store.rs`): every row belongs to a file whose recorded
sha matches the tree, rows of a file that is gone are deleted, and `verify` states that as a count - non-zero
throws the cache away and rebuilds once. `SCHEMA_VERSION` changes what a table means: the next run rebuilds rather
than mix vocabularies. Every half shares the tables, scoped by `files.lang`, and a table is WIDENED
(`rust/fbtcore/src/rows/schema.rs`), never narrowed, when two halves disagree on columns - whichever wrote first
would otherwise decide its shape. C# answers in the SAME tables and columns as python so one query reads both:
`new Reader()` is a call, `[Attribute]` a `decorators` row, `const`/`static readonly` are `consts`, `=>` a
`returns`; `qualname` carries the namespace and `imports.kind` tells `using`/`using static`/alias/`global using` apart.

A CALL ROW IS ANCHORED AT THE NAME CALLED, not at the start of its expression (a chain down the page put three calls
on one line), `callee` is that name and not the chain's text when the receiver is itself a call, and an extension
method's `symbol` is where it is DECLARED (`ReducedFrom`, `src/Map/CsRows/CsSemantics.cs`), never on its receiver -
or "who calls the method I wrote" answers nothing. Each was found by comparing every call site's `symbol` with an
MSBuild-workspace extractor over one real project until all agreed.

REFERENCES COME OFF THE DISK the developer's restore and build wrote (`rust/fbtcore/src/csproj/project.rs`):
`bin/**/<tfm>/*.dll` first (MSBuild already resolved and copied every reference there), then
`obj/project.assets.json`, the referenced `.csproj`, and the framework packs (`dotnet/packs/*.Ref`), in none of
the others and without which nothing resolves. A MISSING REFERENCE IS NOT A FAILURE: Roslyn binds what it can.

GENERATED C# IS LISTED, NOT WALKED (the `<auto-generated>` marker, `.Designer.cs`, `.g.cs`,
`.generated.cs`) - because nearly all the rows of a real tree came from EF model snapshots: gigabytes and hours
became a tenth of the size and minutes. There is NO per-file row budget any more: one cut files at 20 000 rows and
the rest was code nobody could ask about. Never widen the rule to a FOLDER name — `Migrations/` holds
hand-written files, and on a large consumer solution their seed methods (`InsertData` over thousands of lines) are the most
expensive rows of the map: one data project spends most of a minute binding them, all of it inside Roslyn. A CONSUMER
keeps them out with `--map-exclude "**/Migrations/*.cs"` (`sources/glob.rs`, the matcher `--skip-file` shares): compiled, listed as
`excluded`, never walked, and folded into the sha so toggling it re-reads exactly those files. The FILE-LEVEL half applies the same rule one step softer:
a generated file is still joined (its declares/uses are real edges), it is only not fingerprinted.

A PROJECT REACHED AS A REFERENCE IS COMPILED WITHOUT KEEPING ITS TREES; when its own files are mapped the
cache answers with that compilation and they must be put back by path (`CsModels.Build`) — without it
most files silently produced syntax-only rows while every count still looked right.

THE PROJECT FILE IS OBEYED (read by `rust/fbtcore/src/csproj/project.rs`, opened as references by `CsProject.cs`): `obj/**/<tfm>/*.cs` is compiled and never mapped (global
usings), `<DefineConstants>` become `#if` symbols, `<Compile Remove>` files get `compiled = 0` and no rows,
and a ProjectReference is followed to SOURCE through the assets.json CLOSURE. **A project never references
its own `bin` output** — that is over a thousand CS0121 ambiguities and every row unresolved.

`objects` IS A CONSTRUCT (tuple, array, collection expression, initializer) and its slots are `arguments`
rows carrying an `object` id instead of a `call` id. `new Foo(x)` stays a CALL — python parity — so an
initializer slot must not also be an assignment row. `diagnostics` + `files.errors` say what did not bind.

VALUES ARE FOLDED PAST THE COMPILER (`CsFolding.cs`): an interpolation or a concatenation is followed
operand by operand to each declaration, an enum is a NAME (`Demo.Region.US`, or `Demo.Region=6` when the
number names none), and an expression that is not constant still records the symbol it binds to.
`const_kind`/`value_kind` says who worked it out — `const` the compiler, `folded` this pass. A piece that
cannot be known folds to NOTHING: half a path looks like a path.

The C# rows are SEMANTIC where a compilation can be built: files are sent PROJECT BY PROJECT
(`CsModels.Order`), one compilation alive at a time, every file of the project parsed so a partial class
binds. No project, no references, no framework pack → `model` is null, every resolved column is "" and
`files.semantic` is 0. Never let a resolved column be filled by a guess — an empty one is the honest answer.

A RESTORED, NEVER-BUILT TREE is the common case, and three rules keep it bound (`csproj/project.rs`, `CsProject.Winners`, `fingerprint` in `mapper/deep/driven.rs`):
an assembly name shipped by both a package and the framework goes to the HIGHER assembly version, the framework
on a tie (a `System.Runtime/4.3.0` facade once shadowed the framework's own - thousands of errors, many calls
unbound); the global usings a build would write (`ImplicitUsings`, `<Using>` items, `Directory.Build.props`)
are synthesized when no `GlobalUsings.g.cs` exists; and each file's sha is salted with its project's
`.csproj` / `project.assets.json` / props, so a restore re-reads the rows it invalidates. Three more: a project's `<Compile Remove>`
stays removed when its compilation came from the REFERENCE cache (it read as compiled, model-less, every call
unbound); the C# version is the project's `<LangVersion>` or its framework's default, never the parser's newest
(C# 14 first-class spans turned `array.Reverse().ToArray()` into CS0023); and `nameof(x)` carries what `x` names.
A package's own `build/*.targets|props` `<Reference HintPath>` is referenced too (`rust/fbtcore/src/csproj/targets.rs`, read as
XML, a condition it cannot judge is FALSE): MSTest adds the assembly holding `TestContext` that way, in no `compile` asset.

WHAT ELSE A PROJECT COMPILES AGAINST lives in `rust/fbtcore/src/csproj/framework.rs` (a large consumer solution: hundreds of compile errors, every one a map artifact):
a `net4x` project against the .NET FRAMEWORK targeting pack - its `<Reference Include>` items, the packages'
`frameworkAssemblies`, the facades and the SDK's netstandard support facades - never the .NET pack; a
`netstandard2.x` project against `netstandard.dll`, never the runtime (whose `System.Private.CoreLib` then leaked
into every net472 consumer as CS0012); and every `<Reference HintPath>`.

`.razor` AND `.cshtml` ARE COMPILED AS THE C# THE RAZOR COMPILER GENERATES (`CsInputs/CsRazor.cs`, the engine of
`Microsoft.AspNetCore.Razor.Language` 6.0 called in process - a source generator cannot load in NativeAOT) and
WALKED AS THE MARKUP FILE (`CsRowsRazor.cs`): rows take the `#line`-mapped line, a row anchored in `#line hidden`
code is dropped, the generator's calls (`__builder.*`, `Write`) are no call rows, and an error in hidden code does
not count. Components go through TWO passes - declarations, discovery over a compilation, full generation - or
`<Badge />` is markup and `razor_renders` is empty. A view's base type and namespaces come from the MVC `Web.config`
beside it (`<pages pageBaseType>`), appended as directives at the END so no line moves, and MVC 5's `@helper` is
rewritten on its own lines to a local function (`object`, `return null`). A markup file's sha folds in its
`Web.config`/`_Imports`/`_ViewImports` chain. A `*.Generated.cs`
is walked for the map (`generatedCs` in `Sources.Collect`) so it keeps its `files` row.

A FOLDED VALUE IS THE VALUE WHERE IT IS READ (`CsFolding.Initializer`/`Written`): a local folds only when nothing
in its member writes it again (assignment, `++`/`--`, `ref`/`out`), a field or property only when readonly or
get-only and never assigned in its type; and only a STRING `+` is a concatenation. Folding the initializer
recorded half the sampled values of a large consumer solution wrong - `i + 1` as "01".

A FILE'S CONTENT HASH IS THE TREE MAP'S (`mapper/deep/hashes.rs`): `fbt` keeps a snapshot under `<root>/.fbt/deep.sqlite`,
bounded by the map's `--skip`, and re-reads only what the journal or size/mtime says moved - a per-turn hook no longer
reads thousands of files to find three. A file it does not name is read as before, and one that will not OPEN is dropped either
way (a sha recorded without rows fails the store's invariant on every run). `.fbt/` ignores itself (`tree::ignored`), and
the Angular half's own fingerprint skips it, or every gate run would read as a changed workspace.

WHAT THE BUILD COMPILED BEATS WHAT THIS MAP RECONSTRUCTS (`csproj/recorded.rs`): wherever `StructureGate.targets` is
imported, `StructureGateRecordInputs` writes `obj/<config>/<tfm>/structuregate.inputs.tsv` after CoreCompile - the
build's own references, defines (the SDK's `NET10_0_OR_GREATER` & co, which the reconstruction never had), language
version and Compile items - and a record NEWER than the `.csproj` replaces the reconstruction. Everywhere else the
rules above still decide.

A FRESH RUN IS ROSLYN'S TIME (a large consumer solution, C# only: rows are most of the run; compile is seconds with a warm file cache
and minutes on the first run of a series, with memory still free - the cache, not paging; the body-diagnostic pass is about a fifth of the rows). The store overlaps the next batch
(`driven.rs`, one writer, in order) and a project's trees are parsed on every core in list order. **Binding every model
ahead on all cores (`GetDiagnostics` in parallel) was tried and REVERTED**: it cost more than it saved on that solution and
changed what Roslyn reported - a few extra `CS0246` in one project that a serial run does not
see. **Reading each file's rows on its own thread (merged in order, ids renumbered) was tried and REVERTED too**:
rows barely faster than serial - Roslyn's binding contends with itself - the whole run nearly twice as slow, and the
SAME CS0246 (identical table hash). It is concurrent binding across the solution's projects that changes the
answer: that project's slice alone does not reproduce it. Anything parallel here is proven against the release's rows on
the WHOLE of that solution first.

THE PASSES OVER THE FINISHED ROWS (SQL links, seed walk, row search, atlas) ARE NOT RUN AGAIN OVER THE SAME ROWS
(`mapper/deep/derived.rs`): their key is every `files` row's lang/path/sha, the id counters, the TS setup, the SQL
config, the optional outputs asked for and the running build; their notes and table counts are replayed from `_meta`
so a skipped run prints the same. The file list is in the key for a DELETE - dropping rows hands out no new id.

A PAYLOAD HALF WHOSE INPUTS DID NOT MOVE IS NOT LAUNCHED (`payload.rs`): its key - every root's tree-map hash, the
file list it is given, its scripts, `host --version`, its arguments, the borrowed `typescript` - is stored in `_meta`
as `skip:<lang>`, and only after a run that stored cleanly and added no error, so a file that does not parse is
reported on every run.

**BUMP `CS_ROWS_VERSION` (`rust/fbtcore/src/mapper/deep/driven.rs`) WITH EVERY CHANGE TO WHAT THE C# EXTRACTOR WRITES** - it is folded into each file's
sha, like PyRows' `ROWS_VERSION`. Without a bump an upgraded gate keeps the old gate's rows wherever the source and
references did not move: a consumer solution kept its old bound share after the fixes that raise it, until its database was deleted.

`enums` AND `switch_cases` ARE SHARED WITH THE TYPESCRIPT HALF (`CsBody/CsRowsCases.cs`): same table,
its shape, so a backend value joins a frontend one. Each half deletes only its own - C# by `file`, TypeScript by
`half` (or by its own `owner_file` ids on a partial run) - and **only a FULL TypeScript run proves that**: a partial
one deletes by ids that are never C#'s, so a case that only edits files passes against a delete that wipes C#'s rows
(`TsRowsBranches` adds a new `.ts` file to force one).

THE FILE MAP'S C# EDGES TAKE THE COMPILER'S WORD ONLY WHERE THE NAME CANNOT CHOOSE: `file_refs` holds, per bound
file, the mapped files its symbols are declared in (`CsRowsBody.Reach`, off symbol locations - never parsed back out
of `symbol` strings), read back after the deep map into `File::bound`, and the join uses it only for a name several
files declare, and only among the files that declare it NOW: an unchanged file keeps its rows when the file it bound
to moves, so a target is never an edge on its own word. A type `refs` row names the DEFINITION (`Demo.Pipeline<TReq,
TRes>`, as `classes.symbol` does), and generic and qualified type names are rows too.

A SOURCE GENERATOR CANNOT RUN HERE (NativeAOT loads no analyzer), SO WHAT IT WROTE IS READ (`csproj/project.rs::emitted`):
every `.cs` under `<newest tfm>/generated/**` or `<CompilerGeneratedFilesOutputPath>` - there only when the project sets
`<EmitCompilerGeneratedFiles>` - is compiled and never mapped, on the recorded path too, except the Razor generator's
folder (`CsRazor` regenerates it; both declare every component twice). A file the walk already brought in is not
compiled again. The emitted files' sizes and times are in the project fingerprint, so a build that writes them re-reads
the files they complete. CS8795/CS0762 - a partial with no body - are `kind = 'generator'` and not `files.errors`.

A RE-READ SAYS WHY (`mapper/deep/reasons.rs`): `reasons::salted` is the ONE place a file's sha is folded, and the
fingerprint is `Inputs::fingerprint_parts` joined with `+` - change either and every recorded sha moves, so every file
of every consumer is re-read once. The parts are kept in `_meta` as `fingerprints:csharp` (written only when one moved)
so a moved file can be folded again with its project's parts THEN and told apart: content, project (and which input),
new, rows version, `--map-exclude`. `_meta.last_refresh` (`refresh.rs`) is rewritten by every run that did work (re-read, ran the passes, or failed); a run that did nothing leaves it and the last-run trace as they were. No key may read it.

A REFERENCED PROJECT UNDER A `--skip` FOLDER (below a root, never above it) is bound through its build's `bin/**/<Name>.dll`
when one exists (`CsInputs/CsSkipped.cs`), not compiled from source - that was seconds of a large consumer's refresh for rows nobody asked
for. Without a build it is compiled as before, so a skip never costs a mapped file its binding.
